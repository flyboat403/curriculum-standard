# 错误处理与回退决策树

仅在生成过程出现故障时读取本文件。

## 故障1：PDF解析失败
```
PDF解析是否成功？
├─ 成功 → 继续Phase 1提取
├─ 部分成功（部分页面失败） →
│   ├─ 关键页面（培养目标、课程设置）失败 → 询问用户：是否有关键页面截图或文本？
│   │   ├─ 有 → 使用截图OCR或手动输入
│   │   └─ 无 → 使用现有信息继续，标记缺失部分
│   └─ 非关键页面失败 → 使用现有信息继续
└─ 完全失败 →
    ├─ 尝试使用OCR工具 → 成功则继续
    ├─ OCR失败 → 询问用户提供纯文本版本
    └─ 用户无法提供 → 报告错误，暂停生成
```

## 故障2：模板文件缺失或损坏
```
模板验证是否通过？
├─ 通过 → 使用用户提供的模板
├─ 用户未提供，默认模板不存在 →
│   ├─ 询问用户：请提供模板文件或确认使用内置模板生成
│   │   ├─ 用户提供 → 使用新模板
│   │   └─ 用户确认内置生成 → 使用SKILL.md中的结构生成基本模板
└─ 模板损坏（无法读取） →
    ├─ 尝试修复（如DOCX转MD再转换） → 成功则继续
    └─ 修复失败 → 使用SKILL.md结构生成基本模板，告知用户
```

## 故障3：学习情境模板读取失败
```
学习情境模板读取是否成功？
├─ 成功 → 使用模板生成学习情境
├─ 部分成功（部分模板缺失） →
│   ├─ 缺失融合版 → 使用标准项目版代替，告知用户
│   ├─ 缺失所有模板 → 使用SKILL.md中的基本结构生成
└─ 完全失败 →
    ├─ 询问用户：是否了解三表格结构？
    │   ├─ 了解 → 按用户指导生成
    │   └─ 不了解 → 使用简化版（基本信息+内容设计+教学设计）生成
```

## 故障4：文档转换失败
```
文档转换是否成功？
├─ 成功 → 验证样式
├─ pandoc失败 →
│   ├─ 尝试其他转换方法（如python-docx库）
│   └─ 所有方法失败 → 生成Markdown文件，提供手动转换指导
└─ 样式不符合 →
    ├─ 手动调整样式（字体/字号/表格格式）
    └─ 调整失败 → 生成标记样式要求的Markdown，提供手动格式化指导
```

## 故障5：内容提取不完整
```
关键信息是否完整？
├─ 完整 → 继续生成
├─ 缺失课程基本信息（名称/学时/专业） →
│   ├─ 询问用户补充缺失信息
│   └─ 用户无法提供 → 使用占位符生成，明确标记缺失部分
├─ 缺失课程内容结构 →
│   ├─ 基于类似课程推断合理结构
│   └─ 推断困难 → 生成通用结构模板，要求用户完善
└─ 缺失学习情境内容 →
    ├─ 基于学时分配生成基本情境框架
    └─ 提供填写指南，要求用户完善具体内容
```

## 通用回退策略
- 首选方法：按 SKILL.md 工作流正常执行
- 一级回退：询问用户提供缺失信息或替代方案
- 二级回退：使用简化版或通用模板生成
- 三级回退：生成带注释的框架文档，提供完善指导

## 错误报告要求
- 必须明确告知用户故障类型和影响范围
- 提供具体可行的解决方案选项
- 记录所有尝试的修复方法和结果
- 最终文档必须标记所有使用回退策略生成的部分

## NEVER
- 不要在不告知用户的情况下静默失败
- 不要生成明显不完整或错误的文档而不标记
- 不要跳过关键验证步骤
- 不要在用户未确认的情况下使用推断值

## Always
- 保留所有中间文件和日志以供调试
- 提供清晰的故障恢复指导
- 确保最终文档至少包含完整结构框架
- 标记所有不确定或推断的内容
